# ポモドーロタイマー 段階的実装計画

各フェーズは **動作確認可能な状態** で区切り、テストも含めて段階的に進めます。

## フェーズ1：バックエンド基盤（機能 #1, #5, #6 + #20, #21）

最も依存が少なく、単体テストで確認しやすい層から着手します。

| ステップ | 内容 | ファイル | 確認方法 |
|---------|------|---------|---------|
| 1-1 | `MemoryStore` 実装 | `store.py` | pytest |
| 1-2 | Store層テスト | `tests/test_store.py` | `pytest tests/test_store.py` |
| 1-3 | `PomodoroService` 実装 | `pomodoro_service.py` | pytest |
| 1-4 | Service層テスト | `tests/test_service.py` | `pytest tests/test_service.py` |

**完了基準**: Store・Service のテストが全て通る

---

## フェーズ2：Flask アプリ骨組み + API（機能 #1〜#4 + #22）

Application Factory パターンでアプリを構築し、API エンドポイントを実装します。

| ステップ | 内容 | ファイル | 確認方法 |
|---------|------|---------|---------|
| 2-1 | `create_app()` + `GET /`（空テンプレート返却） | `app.py` | ブラウザで `/` アクセス |
| 2-2 | `POST /api/complete` 実装 | `app.py` | curl / テスト |
| 2-3 | `GET /api/stats` 実装 | `app.py` | curl / テスト |
| 2-4 | APIテスト | `tests/test_app.py` | `pytest tests/test_app.py` |

**完了基準**: 全APIが `test_client` で動作確認済み

---

## フェーズ3：UIの静的構造（機能 #7, #8）

| ステップ | 内容 | ファイル | 確認方法 |
|---------|------|---------|---------|
| 3-1 | HTML テンプレート（カードレイアウト、SVG円形プログレス、ボタン、進捗欄） | `templates/index.html` | ブラウザで見た目確認 |
| 3-2 | CSS スタイリング（紫系テーマ、レスポンシブ） | `static/css/style.css` | モックアップ画像との比較 |

---

## フェーズ4：タイマーのカウントダウン動作（機能 #9, #11〜#14）

フロントエンドのコアロジックを実装します。

| ステップ | 内容 | ファイル | 確認方法 |
|---------|------|---------|---------|
| 4-1 | `TimerCore` クラス実装（DOM非依存） | `static/js/timerCore.js` | jest テスト（任意） |
| 4-2 | 開始ボタン → カウントダウン動作 | `static/js/timer.js` | ブラウザで動作確認 |
| 4-3 | リセットボタン動作 | `static/js/timer.js` | ブラウザで動作確認 |
| 4-4 | SVG 円形プログレスリング更新 | `static/js/timer.js` | 残り時間に連動して円弧が減る |

**完了基準**: 開始→カウントダウン→0:00到達、リセットでリセットされ、プログレスリングが連動する

---

## フェーズ5：API連携 + 進捗表示（機能 #18, #19）

タイマー完了時にバックエンドと通信し、進捗を画面に反映します。

| ステップ | 内容 | ファイル | 確認方法 |
|---------|------|---------|---------|
| 5-1 | 作業完了時に `POST /api/complete` 送信 | `static/js/timer.js` | ブラウザ DevTools で通信確認 |
| 5-2 | 進捗表示エリアを `GET /api/stats` で更新 | `static/js/timer.js` | 完了後に完了数・集中時間が更新される |
| 5-3 | ページ読み込み時に進捗を取得 | `static/js/timer.js` | リロード後も進捗が表示される |

**完了基準**: ポモドーロ完了 → 進捗数が増加し、集中時間が更新される

---

## フェーズ6：状態遷移の自動切替（機能 #15〜#17）

最も複雑なロジックを最後に実装します。

| ステップ | 内容 | ファイル | 確認方法 |
|---------|------|---------|---------|
| 6-1 | 作業完了 → 短い休憩（5分）への自動遷移 | `timerCore.js` + `timer.js` | 作業終了後にステータスが「休憩中」に変わる |
| 6-2 | 休憩完了 → 次の作業への自動遷移 | 同上 | 休憩終了後にステータスが「作業中」に戻る |
| 6-3 | 4回目の作業完了 → ロングブレイク（15分） | 同上 | 4回目の後にロングブレイクが始まる |
| 6-4 | ステータス表示（「作業中」「休憩中」）の切替 | `timer.js` | 画面上部の表示が連動して切り替わる |

**完了基準**: `IDLE → WORKING → SHORT_BREAK → WORKING → ... → LONG_BREAK` の状態遷移が正しく動作する

---

## まとめ

```
フェーズ1  バックエンド基盤     ← テスト駆動で安心して構築
フェーズ2  Flask API           ← curlで即確認
フェーズ3  UI静的構造           ← 見た目を先に固める
フェーズ4  タイマー動作         ← ここで初めて「動くアプリ」になる
フェーズ5  API連携+進捗        ← フロントとバックが繋がる
フェーズ6  状態遷移            ← 最後に複雑なロジックを追加
```

各フェーズは独立して動作確認できるため、問題があれば早期に発見・修正できます。
